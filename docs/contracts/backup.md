# عقد صيغة النسخة الاحتياطية

> **كتبته P10 (2026-11-02) ومجمَّد.** يحدد ملف النسخة الاحتياطية للمكتبة كلها (R45): ترويسته، وإصداره، وبصمة سلامته، وأقسامه، وقواعد التحقق، وسياسة التخطي الافتراضية. **تنفّذه P13** في `src/core/backup/` وصفحتي المحفوظات والإعدادات، وتملأ رموز `BK_` في `src/core/errors/backup.js`. والتحويل بين الحزمة ومدخل النسخة في النموذج (`bundleToBackup` و`bundleFromBackup`، عقد البيانات §١٣)، والكتابة بـ`store.restoreVideo` (عقد التخزين §١٠)، فلا تعرف P13 شكل المفاتيح.

## ١. الملف

- ملف JSON واحد بترميز UTF-8، اسمه `tarjuman-backup-YYYY-MM-DD.json` (تاريخ الإنشاء بتوقيت UTC)، يُحفظ بـ`saveFile` (عقد الواجهات §١٣) فيتبع «مكان حفظ ملفات الترجمة».
- **محلي بالكامل:** لا يُرسل إلى أي مكان، ولا يدخل محتواه التشخيص أبدًا (الأعداد والرموز وحدها).
- الحد `BACKUP_LIMITS.maxBytes` = 512 م.ب **بالبايت الفعلي**: ما فوقه يُرفض قبل قراءته (`File.size`). والحد نفسه للإنشاء (بايتات UTF-8 للنص المبني، `utf8Length`) وللحفظ من الصفحات (`SAVE_LIMITS.maxPageBytes`، عقد الواجهات §١٣)، فلا يُنشأ ولا يُحفظ ملف يرفضه القارئ (تدقيق 7a66f91، U55، قرار Q28؛ كان الحفظ بحد 256 مليون وحدة UTF-16 فتُحفظ نسخة CJK فوق 512 م.ب ثم تُرفض).

## ٢. الترويسة والأقسام

```js
BackupFile = {
  format: "tarjuman-backup",              // ثابت؛ غيره «ليس نسخة احتياطية من ترجمان»
  version: 1,                             // إصدار الصيغة (BACKUP_VERSION)؛ مستقل عن meta.schema
  createdAt: "ISO",
  app: { version: "0.3.0", storageSchema: 1 },
  options: { previous: true },            // هل ضُمّنت النسخ السابقة (Q13: نعم افتراضيًا، وتُستبعد بخيار)
  counts: { videos, translations, previous, marks, settings: boolean, prefs: boolean },
  integrity: { algorithm: "SHA-256", hash: "<64 محرفًا ست عشريًا>" },
  data: {
    settings: Settings | null,            // عقد البيانات §٨
    prefs: Prefs | null,                  // عقد البيانات §١٤ (ومنه القاموس)
    videos: BackupVideo[]                 // الأقدم إنشاءً أولًا، ومعرّف الفيديو فريد
  }
}
```

المفاتيح بالضبط كما أعلاه (المجهول فشل)، وكلها موجودة. وفي `data` قسمان اختياريان بعد إصداريهما: `langPrefs` منذ الإصدار 2 (§٨)، و`glossaries` منذ الإصدار 3 (§٩).

## ٣. مدخل الفيديو

```js
BackupVideo = {
  record: VideoRecord,                         // عقد البيانات §٦ حرفيًا: rev وcreatedAt وupdatedAt كما خُزّنت
  active: 1 | 2 | 3 | null,
  names: [string | null, string | null, string | null],
  alts: [AltSlot | null, AltSlot | null, AltSlot | null],   // عقد التخزين §٧؛ خانة النشطة null
  previous: Previous | null,                   // null إن استُبعدت (options.previous = false)
  marks: [{ marks: Mark[], position: Position | null }, …×3]
}
```

- `bundleToBackup(bundle, { includePrevious })` يبنيه من الحزمة، و`bundleFromBackup(entry)` يعيد `{ ok: true, bundle }` أو `{ ok: false, path, reason }` بمدققات النموذج نفسها وثوابت الحزمة (عقد البيانات §١٠).
- الحزمة كما هي بلا اشتقاق: لا رأس ولا ملخص ولا `base` (يحسبها التخزين عند الكتابة).

## ٤. بصمة السلامة

- `integrity.hash` = SHA-256 (`crypto.subtle.digest`) لبايتات UTF-8 من `JSON.stringify(data)` المضغوط بترتيب المفاتيح كما كُتب. والتحقق: قراءة الملف، ثم `JSON.stringify` لـ`data` المقروء، ثم البصمة والمقارنة. فالمسافات خارج `data` لا تهم، وأي تغيير داخله لا تُعاد معه حساب البصمة يُكشف. **بصمة سلامة لا توقيع:** من عدّل `data` وأعاد حسابها فلن يُكشف، فلا تستعد ملفًا من مصدر لا تثق به.
- `counts` للمعاينة السريعة؛ ويُعاد حسابها من `data` بعد التحقق، واختلافها فشل سلامة.

## ٥. قواعد التحقق بالترتيب

| الخطوة | عند الفشل | الرمز (تملؤه P13) |
| --- | --- | --- |
| الحجم ≤ 512 م.ب | يُرفض الملف كله، ولا يُقرأ | `BK_TOO_LARGE` |
| JSON صالح، و`format` الثابت، والمفاتيح بالضبط | يُرفض كله | `BK_NOT_BACKUP` |
| `version` ≤ المدعوم | الأحدث يُرفض كله ولا يُكتب شيء («حدّث ترجمان أولًا»)؛ والأقدم يمر بخطوات ترقية صيغة الملف (لا توجد قبل 1) | `BK_VERSION_NEWER` |
| `integrity` و`counts` | يُرفض كله | `BK_INTEGRITY` |
| `settings` و`prefs` | قراءة متسامحة (`normalizeSettings` و`normalizePrefs`) ثم تحقق صارم؛ التالف يُستبعد وحده بتحذير يسمّي المجموعات بأسمائها للمستخدم | `BK_SETTINGS_INVALID` |
| كل فيديو بـ`bundleFromBackup`، ومعرّفه فريد | **فشل جزئي صادق:** الفيديو التالف يُعرض «تعذّر» بسببه ويُتخطى، والباقي يمضي | `BK_VIDEO_INVALID` |

لا كتابة قبل اكتمال التحقق كله والمعاينة.

وتقوية القراءة (تدقيق 7a66f91، U59): ملف بتداخل عميق جدًا يقبله `JSON.parse` ويرمي تسلسله العودي يُرفض `BK_NOT_BACKUP` لا «خطأ غير متوقع»؛ ومحارف تجاوز الاتجاه وعزله (U+202A–U+202E وU+2066–U+2069) تُجرَّد من حقول `title` و`fileName` في المدخل قبل تحققه كما في الاستيراد، وعلامات الاتجاه المشروعة (U+200F) تبقى.

## ٦. المعاينة وسياسة الاستعادة

- **المعاينة** قبل أي كتابة: الأعداد (فيديوهات، وترجمات، وسابقة، وعلامات)، ومجموعة «جديدة» (معرّفها غير محفوظ) ستُضاف، ومجموعة «موجودة».
- **الموجود يُتخطى افتراضيًا.** والموجود غير المقروء (بلا مُلخّص) تحمل معاينته بصمة قيمه الخام (`store.rawPrint`) في `expect: { print }`، وتُقارَن عند الكتابة داخل طابور الكاتب فلا تطمس الاستعادة إصلاحًا أحدث (`changed`، تدقيق V2، U-023). والاستبدال باختيار صريح لكل صف، أو «استبدال كل الموجود» بنبرة `danger`. واستبدال الاستعادة للفيديو كاملًا (لا لخانة)، فلا يحفظ سابقة؛ ولذلك يعرض الحوار «نزّل نسخة من بياناتك الحالية أولًا».
- **«استعادة الإعدادات والقاموس» غير مختارة افتراضيًا**؛ وعند اختيارها `setSettings` و`setPrefs` بما في الملف، **كتابتان بحال كل منهما** (`report.parts`، تدقيق 7a66f91، U54): تعذّر إحداهما لا يمنع الأخرى، والتقرير يسمّي ما استُعيد وما تعذّر (`BK_RESTORE_SETTINGS_PART_FAILED` أو `BK_RESTORE_PREFS_PART_FAILED` أو `BK_RESTORE_LANGS_PART_FAILED`، أو `BK_RESTORE_SETTINGS_FAILED` للإعدادات والقاموس معًا، أو `BK_RESTORE_SETTINGS_LANGS_FAILED` حين تتعذّر اللغات مع غيرها)، و«أعد المحاولة» تكتب المتعذّر وحده (`retrySettings`) فلا تمحو تغييرًا أجراه المستخدم بعد التقرير في القسم الذي نجح.
- **إطفاء صور المحفوظات** (تدقيق 7a66f91، U05، قرار Q10): `ui` لا يُستعاد، إلا `prefs.ui.thumbnails === false` في الملف (`thumbnailsOff` في `readBackup`)، فيُطبَّق في كل استعادة ولو لم تُختر الإعدادات، وتذكره المعاينة والتقرير. ولا تُشغَّل الصور بالاستعادة أبدًا، والملف بلا الحقل (نسخ `tj-v2` قبل الميزة) يُبقي قيمة الجهاز.
- **الكتابة:** فيديو بعد فيديو بـ`store.restoreVideo(entry, { replace })` (كتابة ذرية واحدة لكل فيديو تحفظ `createdAt` و`updatedAt` كما في النسخة)، بشريط تقدم، ثم تقرير: أضيف · تُخطّي · استُبدل · تعذّر، مع «أعد المحاولة» لما تعذّر وحده. خطأ فيديو (`ST_QUOTA_EXCEEDED` مثلًا) لا يوقف الباقي إلا امتلاء المساحة، فيُوقف ويُبلّغ بما كُتب وما بقي.
- **الإنشاء:** `listLibrary` ثم `getBundle` لكل فيديو، و`bundleToBackup`، والبصمة، ثم `saveFile`. و«تضمين النسخ السابقة» مفعّل افتراضيًا. وما لا يُقرأ (`getBundle` يرفض، أو سجل بلا مُلخّص من `unreadableVideos`) يُذكر في التقرير «تعذّر» برمزه، فلا يدّعي التقرير نسخ ما لم يُنسخ.
- **تابع تالف لا يُسقط الفيديو** (تدقيق 7a66f91، U94، قرار Q29؛ كان الفيديو كله يسقط، والنسخة مسار الانتقال الوحيد إلى نسخة المتجر): إن رفض `getBundle` بـ`ST_CORRUPT_RECORD` قُرئت المفاتيح خامًا (`store.salvageBundle`، عقد التخزين §١٠) وضُمّن السجل إن صح وكل تابع يجتاز مدققه ويتسق معه، وبلا رأس صالح لا تُقرأ التوابع فتُستبعد معه. ويعيد الإنشاء `partial: [{ videoId, dropped }]` فتقول الصفحة إن النسخة جزئية وما استُبعد من كل فيديو (`BK_CREATED_PARTIAL`). ولا يُكتب شيء: **الأصل التالف باقٍ** في التخزين كما هو. والسجل نفسه إن تلف يُتخطى «تعذّر» كما كان.
- **الحجم عند الإنشاء** (U55): بعد بناء النص تُعدّ بايتاته، وما فوق `maxBytes` (أو فوق حد طول النص في المحرّك) يُرمى `BK_CREATE_TOO_LARGE` بالحجم والحد ولا يُحفظ شيء، ويقترح إطفاء «تضمين النسخ السابقة». والإنشاء يعيد `bytes` مع النص.
- **المعاينة** تعدّ السجل المحلي غير المقروء «موجودًا» (يُتخطى افتراضيًا)، فيُختار استبداله لإصلاحه من النسخة.
- **الاستبدال على نسخة المعاينة** (تدقيق 7a66f91، C2، U11): كل فيديو موجود يحمل نسخته كما عُرض (`planRestore(backup, ids, seen)`)، و`restoreVideo` يمرّرها `expect`. فإن تغيّر الفيديو بعد المعاينة لا يُستبدل، ويُعدّ `changed` في التقرير برسالة `BK_RESTORE_CHANGED` وخلاصة «اكتملت إلا…» (`BK_RESTORE_PARTIAL`)، ولا تعيده «أعد المحاولة»: إعادة المعاينة هي التي تعرض حالته الجديدة.

## ٧. اختلاف الإصدارات

- `version` للصيغة وحدها. نسخة الإصدار الثاني (`version: 1`) تُستعاد في الثاني فأحدث، ولا يستعيدها الإصدار الأول (لا استعادة فيه).
- **الإصدارات الثلاثة اليوم** (`BACKUP_VERSION` = 3): كل ملف يُكتب بأدنى إصدار يحمل ما فيه، فلا يُرفع لمن لا يحتاجه. **1** بلا بيانات لغة ولا قوائم أزواج (يستعيده 1.1.0)، و**2** حين في المدخلات بيانات لغة أو تفضيلات لغات غير افتراضية (§٨؛ يستعيده 2.0.0 حتى 2.2.0)، و**3** حين تحمل النسخة قوائم مصطلحات لأزواج (§٩، الفكرة ٨). والقارئ يقبل الثلاثة، وكل قسم اختياري لا يُقبل قبل إصداره. والأقدم يرفض الأحدث برسالة «من إصدار أحدث» (`BK_VERSION_NEWER`) لأن فحص الإصدار يسبق فحص الشكل، لا «ليست نسخة احتياطية».
- `app.storageSchema` للتشخيص؛ والتخزين يبقى `meta.schema = 1` (عقد التخزين §٧).
- رفع `version` تغيير عقد يضيف خطوة ترقية للملفات الأقدم واختبارها.
- **مسودات المحرّر مستبعدة** (الفكرة ٩، ح-48، عقد التخزين §١٦): النسخة تُبنى من الحزم (`getBundle`) والتفضيلات والقوائم، فلا تحمل مفتاح `draft:<id>` ولا نصه، ولا يتغير بها إصدار الملف ولا شكله. فما لم يُحفظ في المحرّر لا تنقله النسخة الاحتياطية؛ احفظه قبلها. والاختبار في `test/integration/compat/drafts.test.js`.

## ٨. بيانات اللغة — 2.0.0 (AA1)

- مدخل الفيديو يحمل `lang` (اختياريًا): `{ sources, prints, slots, previous }` من `lang:<id>` بلا `base`، ويُكتب حين توجد بيانات لغة وحدها (`bundleToBackup`).
- **الإصدار:** الملف بالإصدار **1** حين لا مدخل فيه `lang`، فيستعيده 1.1.0 كما هو؛ وبالإصدار **2** حين يوجد، فيرفضه 1.1.0 بـ`BK_VERSION_NEWER` برسالة لا بفساد صامت. و2.0.0 يقرأ الإصدارين.
- `bundleFromBackup` يتحقق من `lang` بمدققه (`validateLangValue`) وبثوابت الحزمة نفسها (الذهاب والإياب بلا تطبيع صامت).
- **تفضيلات اللغات (AA3):** `data.langPrefs` اختياري في الإصدار **2** وحده (مرفوض في الإصدار 1 بـ`BK_NOT_BACKUP`)، ويُكتب حين تختلف التفضيلات عن الافتراضي، فيصير الملف بالإصدار 2 ولو لم يكن في مدخل `lang`. والافتراضية لا تُكتب، فتبقى صيغة الإصدار 1 كما هي. لا عدّ لها في `counts`، والبصمة تشملها مع `data`.
  - **القراءة** متسامحة لكل حقل (`normalizeLangPrefs`): التالف يعود افتراضيه ولا يسقط غيره. و`readBackup` يعيدها في `langPrefs` (أو `null`).
  - **الاستعادة** مع «استعادة الإعدادات والقاموس» وحدها (`plan.hasSettings` يشملها): الزوج والتذكّر والأخيرة كما في النسخة، وأزواج الفيديوهات **تُضاف** إلى الموجود ولا تمحوه (`applyLangPrefs` بـ`videos`). تُرسَل الأزواج بترتيب `order` (الأحدث آخرًا، تدقيق V2، U-018). نتيجتها في `report.parts.langPrefs` (`restored` أو `failed`، وتبقى نسخة منها في `report.langPrefs`)، وتدخل خلاصة `report.settings` مع القسمين الآخرين ولا يُسقطها دمج إعادة المحاولة، فلا نجاح كاذب (U-021). وتعذّرها وحدها `BK_RESTORE_LANGS_PART_FAILED` (U-022)، ومعها غيرها `BK_RESTORE_SETTINGS_LANGS_FAILED`. وإعادة المحاولة تكتب المتعذّر منها وحده، والاختيار الأصلي يبقى في الصفحة لكل المحاولات.
  - **`order` في الملف:** `langPrefs.order` (معرّفات `videos`، الأحدث آخرًا) يُكتب في الإصدار 2، والقارئ يطبّع ملفًا بلا `order` (نسخ ما قبل الحقل) بترتيب مفاتيحه ولا يرفضه؛ والقارئ الأقدم يُسقط الحقل الفائض لأن `normalizeLangPrefs` يبني ما يعرفه وحده. لا رفع لإصدار الصيغة.

## ٩. قوائم المصطلحات لكل زوج — الإصدار 3 (الفكرة ٨، ح-46، 2026-11-13)

- `data.glossaries` اختياري في الإصدار **3** وحده: القيمة كما في المفتاح `glossaries` (عقد البيانات §١٤، وعقد التخزين §١٥). يُكتب حين توجد قائمة واحدة على الأقل (ولو فارغة)، فيصير الملف بالإصدار 3؛ وبلا قوائم لا يُكتب، ويبقى الملف بالإصدار 1 أو 2 كما كان، فيقرأ نسخَ من لا قوائم له 2.2.0 وما قبله كما كانت. لا عدّ له في `counts`، والبصمة تشمله مع `data`.
- **لماذا الإصدار 3 لا قسمًا في 2:** قارئ 2.2.0 يطبّق `exactKeys` على `data` ولا يسمح في الإصدار 2 إلا بـ`langPrefs`، فنسخة بالإصدار 2 فيها `glossaries` يرفضها «ليست نسخة احتياطية» (`BK_NOT_BACKUP`، ثبت بقارئ `c04a606`)، وبالإصدار 3 «من إصدار أحدث» (`BK_VERSION_NEWER`) برسالة «حدّث ترجمان أولًا». وكذلك قارئ 1.1.0. و`tj-v1` لا استعادة فيه.
- **القراءة** متسامحة (`normalizeGlossaries`): القائمة أو المصطلح التالف يسقط وحده، ويُذكر في تحذير `BK_SETTINGS_INVALID` باسم «قوائم مصطلحات الأزواج» («جزئيًا» إن بقي منها شيء)، ولا يُرفض الملف. وما لا يبقى منه قائمة لا يُستعاد. و`readBackup` يعيدها في `glossaries` (أو `null`).
- **الاستعادة** مع «استعادة الإعدادات والقاموس» وحدها (`plan.hasSettings` يشملها): `store.setGlossaries` بالقيمة كاملة، فتحل محل قوائم الجهاز كما يحل قاموس النسخة محل القاموس العام؛ ونسخة بلا قوائم لا تمس قوائم الجهاز. نتيجتها في `report.parts.glossaries`، ويُبلَّغ عنها في قسم «القاموس والتفضيلات» (`prefsPart`: يتعذّر القسم إن تعذّرت كتابة التفضيلات أو القوائم)، فتأخذ رموز §٦ و§٨ بحاله (تعذّرها بعد نجاح الإعدادات `BK_RESTORE_PREFS_PART_FAILED`)، و«أعد المحاولة» تكتب المتعذّر منها وحده (`retrySettings`).
- **الاختبارات:** `test/unit/backup/backup.test.js` (الإصدار 3 حين توجد قوائم وحده، والاستعادة، والقراءة المتسامحة، وإعادة المحاولة)، و`test/integration/compat/glossaries.test.js` (قارئا 1.1.0 و2.2.0 يرفضان v3 بـ`BK_VERSION_NEWER`، ونسخة بلا قوائم يقرؤها 1.1.0).
