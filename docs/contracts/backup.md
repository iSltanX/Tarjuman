# عقد صيغة النسخة الاحتياطية

> **كتبته P10 (2026-11-02) ومجمَّد.** يحدد ملف النسخة الاحتياطية للمكتبة كلها (R45): ترويسته، وإصداره، وبصمة سلامته، وأقسامه، وقواعد التحقق، وسياسة التخطي الافتراضية. **تنفّذه P13** في `src/core/backup/` وصفحتي المحفوظات والإعدادات، وتملأ رموز `BK_` في `src/core/errors/backup.js`. والتحويل بين الحزمة ومدخل النسخة في النموذج (`bundleToBackup` و`bundleFromBackup`، عقد البيانات §١٣)، والكتابة بـ`store.restoreVideo` (عقد التخزين §١٠)، فلا تعرف P13 شكل المفاتيح.

## ١. الملف

- ملف JSON واحد بترميز UTF-8، اسمه `tarjuman-backup-YYYY-MM-DD.json` (تاريخ الإنشاء بتوقيت UTC)، يُحفظ بـ`saveFile` (عقد الواجهات §١٣) فيتبع «مكان حفظ ملفات الترجمة».
- **محلي بالكامل:** لا يُرسل إلى أي مكان، ولا يدخل محتواه التشخيص أبدًا (الأعداد والرموز وحدها).
- الحد `BACKUP_LIMITS.maxBytes` = 512 م.ب: ما فوقه يُرفض قبل قراءته (`File.size`).

## ٢. الترويسة والأقسام

```js
BackupFile = {
  format: "tarjuman-backup",              // ثابت؛ غيره «ليس نسخة احتياطية من ترجمان»
  version: 1,                             // إصدار الصيغة (BACKUP_VERSION)؛ مستقل عن meta.schema
  createdAt: "ISO",
  app: { version: "0.3.0", storageSchema: 1 },
  options: { previous: true },            // هل ضُمّنت النسخ السابقة (Q13: نعم افتراضيًا، وتُستبعد بخيار)
  counts: { videos, translations, previous, marks, settings: boolean, prefs: boolean },
  integrity: { algorithm: "SHA-256", hash: "<64 محرفًا ست عشريًا>" },
  data: {
    settings: Settings | null,            // عقد البيانات §٨
    prefs: Prefs | null,                  // عقد البيانات §١٤ (ومنه القاموس)
    videos: BackupVideo[]                 // الأقدم إنشاءً أولًا، ومعرّف الفيديو فريد
  }
}
```

المفاتيح بالضبط كما أعلاه (المجهول فشل)، وكلها موجودة.

## ٣. مدخل الفيديو

```js
BackupVideo = {
  record: VideoRecord,                         // عقد البيانات §٦ حرفيًا: rev وcreatedAt وupdatedAt كما خُزّنت
  active: 1 | 2 | 3 | null,
  names: [string | null, string | null, string | null],
  alts: [AltSlot | null, AltSlot | null, AltSlot | null],   // عقد التخزين §٧؛ خانة النشطة null
  previous: Previous | null,                   // null إن استُبعدت (options.previous = false)
  marks: [{ marks: Mark[], position: Position | null }, …×3]
}
```

- `bundleToBackup(bundle, { includePrevious })` يبنيه من الحزمة، و`bundleFromBackup(entry)` يعيد `{ ok: true, bundle }` أو `{ ok: false, path, reason }` بمدققات النموذج نفسها وثوابت الحزمة (عقد البيانات §١٠).
- الحزمة كما هي بلا اشتقاق: لا رأس ولا ملخص ولا `base` (يحسبها التخزين عند الكتابة).

## ٤. بصمة السلامة

- `integrity.hash` = SHA-256 (`crypto.subtle.digest`) لبايتات UTF-8 من `JSON.stringify(data)` المضغوط بترتيب المفاتيح كما كُتب. والتحقق: قراءة الملف، ثم `JSON.stringify` لـ`data` المقروء، ثم البصمة والمقارنة. فالمسافات خارج `data` لا تهم، وأي تغيير داخله يُكشف.
- `counts` للمعاينة السريعة؛ ويُعاد حسابها من `data` بعد التحقق، واختلافها فشل سلامة.

## ٥. قواعد التحقق بالترتيب

| الخطوة | عند الفشل | الرمز (تملؤه P13) |
| --- | --- | --- |
| الحجم ≤ 512 م.ب | يُرفض الملف كله، ولا يُقرأ | `BK_TOO_LARGE` |
| JSON صالح، و`format` الثابت، والمفاتيح بالضبط | يُرفض كله | `BK_NOT_BACKUP` |
| `version` ≤ المدعوم | الأحدث يُرفض كله ولا يُكتب شيء («حدّث ترجمان أولًا»)؛ والأقدم يمر بخطوات ترقية صيغة الملف (لا توجد قبل 1) | `BK_VERSION_NEWER` |
| `integrity` و`counts` | يُرفض كله | `BK_INTEGRITY` |
| `settings` و`prefs` | قراءة متسامحة (`normalizeSettings` و`normalizePrefs`) ثم تحقق صارم؛ التالف يُستبعد وحده بتحذير | `BK_SETTINGS_INVALID` |
| كل فيديو بـ`bundleFromBackup`، ومعرّفه فريد | **فشل جزئي صادق:** الفيديو التالف يُعرض «تعذّر» بسببه ويُتخطى، والباقي يمضي | `BK_VIDEO_INVALID` |

لا كتابة قبل اكتمال التحقق كله والمعاينة.

## ٦. المعاينة وسياسة الاستعادة

- **المعاينة** قبل أي كتابة: الأعداد (فيديوهات، وترجمات، وسابقة، وعلامات)، ومجموعة «جديدة» (معرّفها غير محفوظ) ستُضاف، ومجموعة «موجودة».
- **الموجود يُتخطى افتراضيًا.** والاستبدال باختيار صريح لكل صف، أو «استبدال كل الموجود» بنبرة `danger`. واستبدال الاستعادة للفيديو كاملًا (لا لخانة)، فلا يحفظ سابقة؛ ولذلك يعرض الحوار «نزّل نسخة من بياناتك الحالية أولًا».
- **«استعادة الإعدادات والقاموس» غير مختارة افتراضيًا**؛ وعند اختيارها `setSettings` و`setPrefs` بما في الملف.
- **إطفاء صور المحفوظات** (تدقيق 7a66f91، U05، قرار Q10): `ui` لا يُستعاد، إلا `prefs.ui.thumbnails === false` في الملف (`thumbnailsOff` في `readBackup`)، فيُطبَّق في كل استعادة ولو لم تُختر الإعدادات، وتذكره المعاينة والتقرير. ولا تُشغَّل الصور بالاستعادة أبدًا، والملف بلا الحقل (نسخ `tj-v2` قبل الميزة) يُبقي قيمة الجهاز.
- **الكتابة:** فيديو بعد فيديو بـ`store.restoreVideo(entry, { replace })` (كتابة ذرية واحدة لكل فيديو تحفظ `createdAt` و`updatedAt` كما في النسخة)، بشريط تقدم، ثم تقرير: أضيف · تُخطّي · استُبدل · تعذّر، مع «أعد المحاولة» لما تعذّر وحده. خطأ فيديو (`ST_QUOTA_EXCEEDED` مثلًا) لا يوقف الباقي إلا امتلاء المساحة، فيُوقف ويُبلّغ بما كُتب وما بقي.
- **الإنشاء:** `listLibrary` ثم `getBundle` لكل فيديو، و`bundleToBackup`، والبصمة، ثم `saveFile`. و«تضمين النسخ السابقة» مفعّل افتراضيًا. وما لا يُقرأ (`getBundle` يرفض، أو سجل بلا مُلخّص من `unreadableVideos`) يُذكر في التقرير «تعذّر» برمزه، فلا يدّعي التقرير نسخ ما لم يُنسخ.
- **المعاينة** تعدّ السجل المحلي غير المقروء «موجودًا» (يُتخطى افتراضيًا)، فيُختار استبداله لإصلاحه من النسخة.

## ٧. اختلاف الإصدارات

- `version` للصيغة وحدها. نسخة الإصدار الثاني (`version: 1`) تُستعاد في الثاني فأحدث، ولا يستعيدها الإصدار الأول (لا استعادة فيه).
- `app.storageSchema` للتشخيص؛ والتخزين يبقى `meta.schema = 1` (عقد التخزين §٧).
- رفع `version` تغيير عقد يضيف خطوة ترقية للملفات الأقدم واختبارها.
